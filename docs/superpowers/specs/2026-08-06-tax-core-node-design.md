## 2. Проблема

Налоговая математика Казахстана существует в проекте **в трёх независимых
реализациях**. Проверено 2026-08-06:

| Место | Что содержит | Откуда берёт ставки |
|---|---|---|
| `lib/core/constants/kz_tax_constants.dart` (533 строки) | `calculate910`, `calculateFull910`, `calculateProgressiveIpn`, `calculateMonthlySocial`, ТОО, НДС. Используется в 7 экранах | с сервера, `GET /api/config/tax` ✅ |
| `esep-landing/calculator.html:218+` | `const MRP = 4325`, `IPN_RATE = 0.04`, `SELF_RATE = 0.04`, свой `calcSocial()` | **захардкожено** ❌ |
| `server/src/routes/platform/income_limit.js:34` | `const MRP_2026 = 4325`, лимит 300 МРП | **захардкожено** ❌ |

Сервер уже хранит все ставки в `server/src/routes/tax-config.js` (SEED, ~30
ключей), но потребляет их только Flutter. Два других места про этот источник
не знают.

**Чем это грозит.** Маслихат может менять ставку 910 в пределах ±50%, МРП
меняется законом о бюджете каждый год. При таком изменении лендинг и Platform
API продолжат считать по-старому — и будут показывать клиентам неверные суммы.
Для продукта, который продаётся как «не ошибиться с налогами», это худший
из возможных багов.

**Второе следствие.** Любой новый клиент (веб-фронт, бот, партнёрский API)
сегодня означает четвёртую реализацию.

## 3. Целевая архитектура

```
                    ┌─────────────────────────────┐
                    │  server/src/services/tax/   │
                    │  чистые функции, без БД,    │
                    │  без Express                │
                    │  ЕДИНСТВЕННЫЙ ИСТОЧНИК      │
                    └──────────────┬──────────────┘
                                   │
         ┌──────────────┬──────────┴───────┬──────────────────┐
         │              │                  │                  │
   POST /api/tax/    import прямо      esbuild-бандл      будущий
   calculate         в Platform API    tax-core.js        веб-фронт
         │              │                  │                  │
   Flutter (позже)  income_limit.js   лендинг            React
                                      calculator.html
```

**Ключевое решение: лендинг НЕ ходит в API.** Калькулятор на `esepkz.com` —
это точка входа для холодного трафика, он обязан считать мгновенно и работать,
даже если Railway лежит. Поэтому из того же исходника собирается статический
бандл `tax-core.js`, который кладётся на лендинг. Источник один, а сеть не нужна.

esbuild на машине разработчика работает — проверено 2026-08-06,
`esbuild.exe 0.27.3` собирает бандл. Заблокирован Device Guard только
`dart.exe`, не JS-инструменты.

## 4. Что переносим, а что нет

### В объёме этой работы

| Источник (Dart) | Строк | Куда |
|---|---|---|
| `kz_tax_constants.dart` — расчёты | 533 | `server/src/services/tax/` |
| `form910_service.dart` — `generateXml`, `generateJson`, модель `Form910Data` | 292 | `server/src/services/tax/form910.js` |

Итого ~825 строк Dart → Node. Это порт, а не переписывание: формулы
переносятся один в один.

### Сознательно НЕ переносим сейчас

| Что | Строк | Почему |
|---|---|---|
| `pdf_service.dart` | 1101 | Использует Dart-пакет `pdf`. В Node это другая библиотека — переписывание, а не порт. PDF сейчас генерятся на клиенте и работают |
| `kaspi_parser.dart` | 730 | Разбор выписки на клиенте — это преимущество: файл не покидает устройство. Пересмотреть вместе с веб-фронтом |
| `esf_service.dart` | 308 | Завязан на поток счетов, трогать вместе с ним |

### Flutter-приложение в этой работе НЕ переплюмбливается

Важное решение. Приложение оставляет свою Dart-реализацию как есть.

Причины: (1) оно всё равно читает ставки с сервера, поэтому от дрейфа ставок
защищено; (2) курс — веб-первый, приложение сейчас не в фокусе; (3) любая
правка Flutter идёт вслепую, а выгоды ноль — поведение не меняется.
На нём 14 живых пользователей, ломать их нечем.

Вместо переплюмбливания — **тест на расхождение** (см. §6): фикстуры
фиксируют, что Node и Dart считают одинаково. Если кто-то поменяет формулу
в одном месте — тест покажет.

## 5. Контракт

### Модуль `server/src/services/tax/`

```
tax/
├── rates.js       — чтение ставок из tax-config (БД) + дефолты
├── calc.js        — чистые функции расчёта
├── form910.js     — формирование формы 910 (XML/JSON)
├── index.js       — публичный экспорт
└── __fixtures__/  — эталонные пары вход→выход
```

`calc.js` не знает ни про Express, ни про БД. Ставки приходят параметром —
так функции тестируемы и пригодны для браузерного бандла.

```js
// Все функции принимают rates первым аргументом
calculate910(rates, halfYearIncome, { regionalAdjustment, regionalDiscount })
calculateProgressiveIpn(rates, annualIncome)
calculateMonthlySocial(rates, { bornBefore1975 })
calculateFull910(rates, halfYearIncome, { regionalAdjustment, regionalDiscount, bornBefore1975 })
calculateTooTax(rates, { revenue, payroll, employees, isVatPayer })
selfEmployedLimit(rates)          // → { monthlyTenge, yearlyTenge }
vatThreshold(rates)               // → { thresholdTenge, rate }
```

Формы возврата повторяют Dart-классы, чтобы порт был механическим:
`TaxCalculation910`, `SocialPayments`, `FullTaxSummary`, `TooTaxCalculation`.

### HTTP

```
POST /api/tax/calculate
```

Публичный, без авторизации — тем же калькулятором пользуется лендинг,
а «посчитать налог» не является приватной операцией. Ограничение частоты
как у остальных публичных эндпоинтов.

```jsonc
// запрос
{
  "regime": "910",              // 910 | self_employed | general | too
  "halfYearIncome": 4690000,
  "options": {
    "regionalAdjustment": 0,
    "regionalDiscount": 0,
    "bornBefore1975": false
  }
}

// ответ
{
  "regime": "910",
  "tax":    { "ipn": 187600, "sn": 0, "total": 187600, "effectiveRate": 0.04 },
  "social": { "opv": 8500, "opvr": 2975, "so": 4250, "vosms": 5950,
              "monthlyTotal": 21675, "halfYearTotal": 130050 },
  "grandTotal": 317650,
  "ratesVersion": "2026.03"      // из tax-config, для отладки расхождений
}
```

`ratesVersion` в ответе обязателен: когда клиент показывает не ту сумму,
первый вопрос — по какой версии ставок считали.

### Бандл для лендинга

```
npm run build:tax-core   →   esep-landing/tax-core.js
```

Собирается esbuild'ом из `services/tax/calc.js` в IIFE, глобаль `EsepTax`.
Ставки на момент сборки вшиваются как дефолты — лендингу не нужна сеть.
Сборка входит в CI, чтобы бандл не разъехался с исходником.

## 6. Порядок работ

Волнами. Каждая волна самостоятельна и проверяема — если остановиться после
любой, проект в рабочем состоянии.

### Волна 1 — модуль и фикстуры

Создать `services/tax/`, перенести формулы из Dart. Написать фикстуры:
эталонные пары вход→выход, снятые чтением Dart-исходника.
Ничего пока не подключать.

*Проверка:* `node --test` на фикстурах. Ноль изменений в поведении продукта.

### Волна 2 — Platform API перестаёт хардкодить

`income_limit.js` импортирует `services/tax` вместо `const MRP_2026 = 4325`.

*Проверка:* существующий `server/scripts/test_platform_e2e.js` (24 проверки)
должен пройти без изменений — поведение не меняется, меняется источник числа.

### Волна 3 — лендинг переходит на общий бандл

Собрать `tax-core.js`, заменить в `calculator.html` самописный расчёт.

*Проверка:* прогнать одинаковые входы через старый и новый калькулятор
в браузере, сверить до копейки. Это единственная волна с видимым для
клиентов результатом — на лендинге живой трафик, ошибка видна сразу.

### Волна 4 — HTTP-эндпоинт

`POST /api/tax/calculate` + форма 910.

*Проверка:* e2e-скрипт по образцу `test_platform_e2e.js`.

### Волна 5 — тест на расхождение Dart ↔ Node

⚠️ Сначала добавить шаг `flutter test` в `.github/workflows/build-release.yml` —
**сейчас его там нет**, проверено 2026-08-06. Без этого шага Dart-тест не
выполнится нигде: локально `dart.exe` заблокирован, в CI только сборка.

Затем фикстуры из волны 1 переиспользуются как Dart-тест в `test/`.

*Проверка:* CI. Если формулы разъедутся — сборка падает.

*Прецедент:* в `test/` уже лежат `form200_logic_test.js`,
`form300_logic_test.js`, `kaspi_parser_logic_test.mjs`,
`kaspi_parser_harness.mjs` — проект давно портирует Dart-логику в JS,
чтобы её вообще можно было прогнать на этой машине. Эта спека доводит
приём до конца: JS-версия перестаёт быть тестовой копией и становится
оригиналом.

## 7. Как это проверяется без dart.exe

Device Guard блокирует `dart.exe` на машине разработчика. Правила:

- **Node-код** — тестируется локально, `node --test`. Полноценно.
- **Dart-код** — только сборкой GitHub Actions (`build-release.yml` гоняет
  `flutter build apk` и `flutter build web` — это настоящая компиляция).
  ⚠️ `flutter test` и `flutter analyze` в CI **не запускаются** — то есть
  проверяется компиляция, но не поведение. Добавить шаг `flutter test` —
  часть волны 5.
  Статус без `gh` (не авторизован):
  `curl -s "https://api.github.com/repos/alibekovakarakat5-png/esep/actions/runs?per_page=5"`
- **Лендинг** — в браузере напрямую, это обычный HTML/JS.

Подробнее — в памяти проекта, `flutter-verify-without-dart`.

| Риск | Что делаем |
|---|---|
| Порт формул с ошибкой — продукт начнёт врать про налоги | Фикстуры пишутся ДО переноса, из Dart-исходника. Волна 1 не подключает ничего |

| Ставки в бандле устареют | `ratesVersion` в ответе API; сборка бандла в CI |
| Разъедутся Dart и Node | Волна 5 — общий набор фикстур в обоих тестах |

## 9. Что эта работа НЕ делает
