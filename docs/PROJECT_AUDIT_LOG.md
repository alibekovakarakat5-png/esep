# Журнал аудита Esep

**Режим работы:** сначала исследование и подтверждение причины; изменения в коде или проде — только после явного согласования пользователя.

## Цель на 16–18 сентября 2026

Сделать веб-версию Esep понятной и безопасной для пилота с бухгалтерами и ТОО: проверить реальные сценарии, тарифы, консультанта, налоговые данные и интеграцию с 1С.

## Правила журнала

- Каждая найденная проблема получает дату, доказательство, уровень риска, предполагаемую причину и статус.
- Перед любой правкой фиксируем: **что меняем → почему → как будет работать после → как проверим**.
- Никакие налоговые правила не считаются актуальными без ссылки на первоисточник и даты проверки.

## Проверки среды

### Уточнения повторного ревью 2026-09-17

- Полный аудит прод-веба не завершён. Подтверждение исходным кодом не равно воспроизведению на проде.
- QA-012: отсутствие ключа — возможная причина, подтверждена ветка кода, но не окружение Railway.
- QA-020: две кнопки сами по себе не доказывают причину конкретного дубля. Отсутствие блокировки повторного сохранения, новая UUID и отсутствие уникальности ИИН/БИН подтверждены кодом.
- QA-022: слово «упрощён» в заголовке означает упрощение алгоритма, а не название режима. Код действительно начисляет СН любому ТОО с сотрудниками без проверки режима — это точная причина проблемы.
- QA-023: существующий OCR доступен в мобильной реализации; веб использует заглушку. Быстрой готовой OCR-функции для веба нет.
